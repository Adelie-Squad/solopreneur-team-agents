# ADR-001 — 오케스트레이션 언어: Python

> **층:** policy (권위 문서 — `docs/policy/schema-stability.md` 와 같은 등급)
> **상태:** Accepted
> **결정일:** 2026-08-07
> **결정자:** SoloSquad 개발자(본인)
> **대체:** `docs/ideation/260803-solosquad-architecture-redesign.md` §A1 (TS 유지 권고) —
> 아래 §3 "전제 변경"에 의해 해당 권고의 **근거가 소멸**했다.
>
> **개정 `2026-08-07`(2차)** — §1·§3.4·§5 의 표현을 정정했다. 초판은 "Python 단일 언어"를
> **최종 원칙**처럼 적었으나, 사용자 확인 결과 **목적지는 폴리글랏**이다(메신저 재도입 ·
> 웹사이트 · 대시보드가 계획에 있음). 결론은 그대로이고 **적용 범위가 "v2.0 단계"로 한정**된다.

---

## 1. 결정

**SoloSquad v2.0 은 Python 단일 언어로 전면 재설계·재작성한다.**

- 오케스트레이션 · 하네스 · 러너 · CLI · 온보딩 · 분석 · 스케줄러 — 전부 Python.
- TypeScript/Node 런타임은 **v2.0 에 존재하지 않는다.** 단 이는 **v2.0 단계의 상태**이지
  영구 원칙이 아니다 — 최종 형태는 **Python 코어 + TS 표면의 2언어**다(§5).
- 배포는 **npm 폐기 → git clone**. 기존 사용자는 **npm 설치본을 제거하고 새로 설치**한다
  (버전 체인 마이그레이션 없음). 추후 사용 측정을 포함한 `curl`/`irm` 부트스트랩을 검토한다.
- Discord/Slack 메신저 계층은 **제거**한다. **재도입은 예정된 것이고**, 시점·언어만 미정이다(§5).
  제거 전에 상태 데이터 형식(user-registry · 채널 매핑 · 승인 카드 이력)을 **문서로 기록**한다.
- Docker 역시 클라우드 배포 시점까지 보류한다.

> **따름정리 — 경계는 지금 긋는다.** 목적지가 2언어이므로 Python 코어와 표면 사이의
> **JSON 계약 경계**는 나중에 잘라내는 것이 아니라 **`[1] 계약` 단계에서 함께 설계**한다.
> 초판은 이 경계를 §5 의 *재도입 조건* 으로만 적었으나, 목적지가 확정된 이상 **설계 요구사항**이다.

---

## 2. 배경 — 왜 이 ADR 이 뒤집힌 결론을 담는가

`docs/prd/v1.5.0_orchestration-and-harness-platform.md`(rev4) 와
`docs/ideation/260803-solosquad-architecture-redesign.md` §A1 은 **TS 유지**를 권고했다.
그 권고는 기각되지 않았다 — **전제가 바뀌어 무효화**됐다.

rev4 §0.1 의 논증 구조는 다음과 같았다.

> ⑴ 언어 축은 중립이다(양쪽 근거 0). → ⑵ 따라서 **전환 비용이 유일한 변별력**이다.
> → ⑶ 전환 비용의 최대 항목은 `src/migrations/scripts/` 43스크립트 7,839 LOC 이며,
>    이것이 비싼 이유는 **npm 에 배포된 34개 버전 · 실사용 워크스페이스와의 계약**이기 때문이다.
> → ⑷ 그러므로 TS 를 유지한다.

**⑴ 은 지금도 참이다.** 세션 훅 축에서 Py 의 대가도 0(SDK 미사용), TS 의 우위도 0(같은 이유)이라는
실측은 변하지 않았다. 언어는 여전히 중립이다.

**⑶ 이 거짓이 되었다.** npm 배포를 폐기하고 git clone 으로 전환하는 결정에 의해,
마이그레이션 체인이 지키던 계약의 **상대방이 사라졌다.** 계약이 없으면 계약 이행 코드도 자산이 아니다.

따라서 ⑵ 의 "유일한 변별력"이 무너지고, 판단은 **다시 열린 상태**가 된다.
그 열린 판단에서 Python 이 선택된 근거가 §3 이다.

> **이 ADR 은 rev4 의 분석을 부정하지 않는다. rev4 는 자신이 명시한 전제 위에서 옳았고,
> 그 전제가 사용자 결정에 의해 교체됐다.** 이 구분을 흐리면 §A3(폐기 논거 재유입 차단)이
> 방지하려던 혼란이 반대 방향으로 재발한다.

## 3. 근거

### 3.1 전환 비용의 붕괴 (판단을 다시 연 요인)

| 항목 | rev4 시점 | 결정 이후 |
|---|---|---|
| `migrations/` 43스크립트 7,839 LOC | 🔴 재작성 불가 — 배포 계약 | ⬜ **폐기** — 계약 상대 소멸 |
| npm 34개 배포 버전 하위호환 | 🔴 유지 의무 | ⬜ **없음** |
| `messenger/` 3,624 LOC (discord.js/@slack/bolt) | 🟡 성숙한 SDK 자산 | ⬜ **제거** — 클라우드까지 보류 |
| `paths.ts` 레거시 fallback 다중 계층 | 🟡 하위호환 필수 | ⬜ **폐기** — baseline 단일화 |

제거·폐기 합계 **≈12,758 LOC (49.8k 중 25.6%)**. 남는 재설계 대상은 약 37k LOC 의 *동작* 이며,
그중 상당수는 §3.3 대로 **애초에 살릴 가치가 없는 배선**이다.

번들 자산 98파일(`agents/` 21 · `skills/` 55 · `teams/` 15 · `crons/` 7)은 마크다운·YAML 이므로
**언어 중립 — 이식 대상이 아니다.** 재작성되는 것은 코드뿐이고, 제품의 지식 자산은 100% 승계된다.

### 3.2 실수요 — 요구 기능이 Py 우위 영역에 정확히 놓인다

결정에서 명시된 필요 기능은 **데이터 분석 · 시뮬레이션 · 장기 사이클 작업** 이다.
이는 현 코드에서 다음 모듈에 해당한다.

| 모듈 | LOC | 내용 |
|---|---:|---|
| `analyze/` | 2,413 | eval 채점 · trigger-rate · A/B · train/val split · refine 게이트 · originality |
| `cron/` | 2,584 | 주기 실행 · freq-keyword-miner · trajectory-extractor |
| `engine/` | 3,578 | goal 실행 루프 · evaluator · tracker |
| (예정) VMS 시뮬레이션 | — | `docs/prd/v1.9.0_virtual-market-demand-simulation.md` |

rev4 §0.2 는 Py 생태계 실수요를 *"정확히 한 곳 — v1.9.0 VMS, 현 마일스톤에서 4단계 뒤"* 로 판정했으나,
그 판정은 **VMS 만을 셌다.** 위 표대로 채점·마이닝·평가 산술은 이미 8.5k LOC 규모로 존재하며,
이들은 TS 에서 손으로 구현된 통계 로직이다. Python 에서는 표준 라이브러리 영역이다.

### 3.3 부수 효과 — 근본 원인이 언어 전환으로 소멸한다

ideation §0.3 이 특정한 근본 원인:

> **"host 가 Task 를 가로챌 수 없다"** — Claude Code 네이티브 `Task` 도구에 spawn 을 위임하는 한
> 컨텍스트를 주입할 지점 자체가 없다. 8단계 조립기(`spawn-assembler.ts` 800 LOC)가 **dead** 이고,
> 가드·stop-hook·핸드오프 슬라이서가 전부 같은 이유로 죽어 있다.

이는 TS 라서 생긴 문제가 아니라 **"우리가 spawn 을 소유하지 않아서"** 생긴 문제다.
그러나 전면 재작성은 그 소유권을 되찾는 것을 **기본 전제로 깔고 시작**할 수 있다.
Python 러너가 `claude` 서브프로세스를 직접 띄우면 위임 구간이 **애초에 존재하지 않는다.**

즉 언어 전환의 실질 이득은 "Python 이 낫다"가 아니라
**"죽은 배선을 이식하는 대신 올바른 구조로 처음부터 세울 명분과 기회를 얻는다"** 이다.

### 3.4 언어 상한

**v2.0 시점 1개(Python). 최종 상한 2개(Python + TS).**
rev4 §0.4-5 의 "언어 상한 2개" 규칙은 **상한값 그대로 승계**하되, v2.0 단계에서는
TS 잔존부가 0 이므로(§0.0.4) 실사용 언어가 1개인 상태로 출발한다.

**Rust·Go 등 3번째 언어는 금지.** 이 금지만이 무기한이다.
TS 는 §5 의 로드맵대로 **돌아온다.**

## 4. 기각된 대안

| 대안 | 기각 사유 |
|---|---|
| **TS 유지 (rev4 권고)** | 전제(migrations 계약 · npm 배포)가 사용자 결정으로 소멸. §2 |
| **폴리글랏 — TS 잔존 + Py 신설** (OpenTag 형) | TS 적합 영역이 `messenger/` 뿐이었고 그것이 제거되어 **잔존부가 0**. 폴리글랏의 대상이 사라짐. 원칙은 §5 로 보존 |
| **기계적 1:1 포팅** | TS/Py 경계가 사라져 1:1 자체는 가능해졌으나, dead 코드(조립기 800 LOC, `makePlaceholderMeasurer`)와 레거시 fallback 을 그대로 승계하게 됨. §3.3 의 기회를 버림 |
| **Strangler 병행** | 이행 기간 내내 사용자가 Node + Python 둘 다 요구. npm 폐기로 "항상 동작하는 배포판 유지"의 수혜자도 없음 |
| **pipx 주채널** | rev4 §0.3 기각 유지 — 전제조건 증가. git clone 이 그 자리를 대신함 |

## 5. TS 재도입 로드맵

TypeScript 는 **금지도 보류도 아니다 — 순서상 뒤에 있을 뿐이다.**
아래 3개 계획이 이미 존재하므로 재도입은 *"조건이 맞으면"* 이 아니라 **예정 사항**이다.

| 예정된 TS 수요 | 근거 문서 |
|---|---|
| 메신저(Discord/Slack) 재도입 | 결정 4 — "재도입 여부는 나중에 결정" → **여부는 확정, 시점만 미정** |
| 웹사이트 | 사업계획 |
| 웹 대시보드 | `docs/prd/v1.x-dashboard-interaction.md` |

**재도입 시점의 요건 3가지** (조건이 아니라 그때 지켜야 할 형태):

1. 클라우드 배포(현 `v1.6.0` 계획)가 착수되어, **Node 전제조건을 배포자만 지면 되는** 형태일 것.
2. 대상이 **플랫폼 실시간 I/O · 어댑터 · UI 렌더**로 한정될 것 (OpenTag 분할 원칙).
3. Python 코어와의 경계가 **JSON 계약으로 명시**되어 있을 것 (로컬 stdio ↔ HTTP 승격 가능한 형태).
   → **이 3번은 v2.0 `[1] 계약` 단계에서 미리 만든다**(§1 따름정리). 재도입 시점에
   소급 적용하려 하면 Python 코어를 뜯어야 한다.

> **OpenTag(CopilotKit) 참조 원칙 — 보존:**
> `TS = 플랫폼 실시간 I/O · 어댑터 · UI` / `Python = 에이전트 추론 · 도구 · 분석`
> 분할 기준은 언어 취향이 아니라 **관심사**다. 단 OpenTag 는 호스티드 중개자를 둔
> **배포형 2-서비스**이고 우리는 **로컬 설치 CLI** 이므로, 전제조건 비용이 배포자에게
> 넘어가기 전까지는 이 분할을 적용하지 않는다.

## 6. 재론 금지 조항

다음 논거는 **이 ADR 을 근거로 무효**이며, 재론 시 이 문서를 인용해 종결한다.

1. **"세션 훅이 TS 를 강제한다"** — SoloSquad 는 Claude Agent SDK 를 쓰지 않는다
   (`package.json` 에 `@anthropic-ai/*` 0건). 훅은 이미 shell 훅이다. (rev4 §0.2)
2. **"웹 대시보드가 언어 통일을 요구한다"** — 대시보드는 HTTP 계약으로 접속하며 언어를 강제하지 않는다.
3. **"migrations 자산이 전환을 막는다"** — §3.1 로 소멸. **이 논거를 되살리려면 npm 배포 재개가 선행**이며,
   그 경우 이 ADR 전체를 재검토한다.
4. **"discord.js 자산이 아깝다"** — 메신저는 v2.0 에서 제거되고, **재도입은 §5 로드맵대로 예정**돼 있다.
   지금 코드를 남겨두는 근거가 되지는 않는다. 재도입 시 언어는 그 시점에 §5-2 원칙으로 판단하며,
   그때의 사양서는 **제거 전 기록해 둔 데이터 형식 문서 + git 히스토리**다.
